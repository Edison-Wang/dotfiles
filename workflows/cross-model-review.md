# Workflow: 三模型交叉檢查

## 觸發
高風險、低可逆性的決策。錯了代價很大。
例如：選資料庫、設計 API contract、挑部署架構。

## 為什麼存在
不同的前沿模型有不同的盲點。同一個問題跑三家，
共識代表穩健，分歧代表需要更深的思考。

## 階段

### Stage 1: 框定問題
寫一份簡報（< 1000 字）：
- 要做的決定（一句話）
- 為什麼重要（錯了的後果）
- 限制（不能改的）
- 候選方案（至少 2 個）
- 評估標準

### Stage 2: 獨立跑
同一份簡報分別丟給：
- **Claude Opus 4.7**
- **GPT-5.5 Pro**（或 Thinking）
- **Gemini 3.1 Pro**

每家問：
1. 你的建議和理由。
2. 反對你自己建議的最強論點。
3. 成本最低的驗證實驗。
4. 你的建議依賴什麼假設。
5. 什麼條件下你會改主意。

**不要把一家的答案給另一家看。獨立性很重要。**

### Stage 3: 比較
三份回答並排看：
- **共識**: 三家都同意 → 高信心。
- **2 vs 1**: 調查少數方為什麼不同意 — 通常它看到了其他兩家遺漏的。
- **三方分裂**: 問題本質上是開放的，你的 context 才是決定因素。

### Stage 4: 寫自己的決定
融合三家觀點，寫你自己的決策文件。標註哪家提出了哪個觀點。

### Stage 5: 存 ADR
`decisions/<日期>-<標題>.md`

## 什麼時候不要用

- 可逆的決定（直接挑一個試）
- 你已經有足夠資訊的決定
- 日常 coding（用一個工具就夠）
